# Decisions

One line of context per entry. Add new ones at the bottom with the next number, and never renumber.

| # | Decision | Why |
| --- | --- | --- |
| D1 | Godot 4, Compatibility (OpenGL) renderer | Frame-timed tweens and shaders for premium motion; low processor mode gives near-zero idle cost on a J4105 |
| D2 | Daemon is one stdlib Python file | It must see global keys while another app has focus; no pip dependencies on the box |
| D3 | IPC is newline JSON over TCP 127.0.0.1 with a token | Godot 4 has no Unix-socket API; the token stops other local processes driving it |
| D4 | X11 only, with LightDM pinned to the Cinnamon X11 session | Window raising, closing and xprop listing all rely on X11; About warns if the session isn't x11 |
| D5 | Home closes the running app; one app at a time; `keep_on_home` opts out | Saves power and memory, and the apps remember where the viewer was |
| D6 | Return to Bosca Mór closes windows politely and does not log out | The launcher lives in the same session; a logout restarts everything and is slow on the J4105 |
| D7 | Force-close desktop windows with `xkill -id`, never by PID | Flatpak windows can report a sandbox-local PID |
| D8 | The name "Bosca Mór" never appears in the UI | Chief's call; a small, understated boot splash is the only exception |
| D9 | Spotify and Alaris Music (Music Assistant Companion) are mouse-driven and accepted for v1 | No better HTPC clients known yet |
| D10 | Firefox tiles each get `--new-instance` and their own `--profile` | Otherwise Firefox hands the URL to a running instance and the launched PID exits at once |
| D11 | The G20S voice button does nothing | Chief's call |
| D12 | Brand logos are never committed | Trademarks; they go in `~/.config/boscamor/icons/` on the box |
| D13 | Jellyfin uses the flatpak's TV fullscreen entry; args deferred to step 10 | The four start-menu entries exist, but their Exec lines haven't been read yet |
| D14 | Home layout values not in the SPEC tables (paddings, gaps, top bar and hint sizes, `#d6d6e0` status text, `#2a2a3c` key pill) are tokens taken from `Main.dc.html` | The SPEC tables cover the main tokens only; the design canvas holds the rest |
| D15 | DM Sans ships as the static 24pt and 40pt optical-size cuts (googlefonts/dm-fonts), not the variable font; sizes 32 px and up use 40pt | MSDF draws the variable font's overlapping contours with visible artifacts |
| D16 | Pointer mode needs a straight-line move of 40 px from any point the pointer was at in the last 250 ms; the wheel never changes mode; a left click launches only the tile under the pointer | SPEC says "a move of 40 px within 250 ms"; displacement, not path length, ignores gyro jitter that wobbles back and forth |
| D17 | Reduce motion snaps movement (scale, position, rise, nudge) to its end value and plays only fades and colour changes, at half duration | SPEC says "crossfades only, all durations halved" |
| D18 | `launch_requested` fires as the launch zoom starts, `launch_faded` when it ends; Home ignores input until `play_return()` | The daemon can start the app during the fade; a second press must not launch twice |
| D19 | The end-of-carousel nudge moves the whole row 12 px in the pressed direction and back | SPEC names the nudge but not what moves |
| D20 | Held arrow keys repeat on the launcher's own timer (400 ms, then 110 ms), like pads; OS key echo for nav keys is dropped | Chief found OS key repeat too fast on Home; X11 repeats at 25 a second and the G20S sends arrow keys. SPEC said keyboard echo covers keys |
| D21 | The power confirm hides the sidebar, as in `Power.dc.html`; Back or Cancel brings the sidebar back with the blur captured when it first opened. The focused confirm button is filled, the other outlined, as the Still open buttons are. After the action, a black "Shutting down" or "Restarting" screen (the design's off view) ignores all input | The design shows these states; SPEC gives only the navigation |
| D22 | The sidebar blur is a 5x5 Gaussian over the quarter-size capture, radius 3 texels (about 12 px at full size) | SPEC asks for a blur but sets no strength |
| D23 | While on Desktop, the launcher window regaining focus also brings Home back | On the dev machine there is no daemon to send Home; on the box the daemon does it |
| D24 | In pointer mode, hovering a sidebar item or confirm button highlights it at once, without the 120 ms dwell | The dwell guards the tile carousel against air-mouse drift; menus and dialogs only appear after a deliberate press |
| D25 | `launch` carries `"keep_on_home"`, and the daemon sends `{"evt":"memory_warning","id","available_mb","app_mb"}` | The daemon needs keep_on_home to decide what Home does; SPEC says the launcher shows the memory warning but gives no message for it |
| D26 | `BOSCAMOR_DRY_RUN` covers the power commands (and, from step 8, `xkill`). SIGTERM and SIGKILL to the daemon's own app process groups still happen under dry run | The tests must prove Home ends the app, and those signals only ever reach processes the daemon started |
| D27 | If the launcher has not reported `state visible` 500 ms after `show`, the daemon runs `wmctrl -F -a Launcher` | SPEC names the fallback but not when it fires; the window title is "Launcher" because the product name never appears in the UI |
| D28 | With no daemon reachable, DaemonClient stands in: it logs each call, and after 1.5 s pretends the app exited or the power-off was a dry run | The Windows dev machine has no daemon, and the launcher would otherwise sit on black after a launch |
| D29 | The daemon also takes `BOSCAMOR_RUNTIME_DIR` and `--no-evdev` | Tests and the integration check run it without `/dev/input` and with their own runtime folder |
| D30 | The top bar Wi-Fi icon reads `/proc/net/wireless` every 30 s: shown when a wireless interface has a link, struck through (`#a3a3b8`) when it has none, hidden when there is no wireless interface (a wired box), shown when there is no `/proc` (dev machine) | SPEC asks for Wi-Fi state without saying how to read it or what a wired box shows; no binaries, no per-frame work |
| D31 | The D23 dev shortcut only fires once the window is no longer minimised, and hiding minimises last | On Windows, minimising delivers a focus-in at once, which un-hid the launcher halfway through hiding it |
| D32 | Settings preferences (reduce motion, screen size, button names) live in state.json beside the remembered state | apps.json is the app list; SPEC names no other config file, and step 3 already read reduce motion from state |
| D33 | Display's UI scale is "Screen size": 100%, 95% or 90%, shrinking the whole launcher round the centre | A TV that overscans crops the edges; growing past 100% would push the 1920x1080 layout off screen |
| D34 | The on-screen keyboard has no design: a dialog-style panel with the field and five rows of 84 x 72 px keys, 10 px apart, focused key filled like other focus | SPEC lists the keys only |
| D35 | The on-screen keyboard reads typed characters from key events, the one exception to Law 1; Backspace has its own `text_delete` action so it deletes rather than going Back | Text entry needs characters, and Backspace is also bound to `back` |
| D36 | A `move` action (pad Y, the Menu key, M) picks up an app row; Up and Down move it; Move, OK or Back drop it and write apps.json | The design's "Y Move" hint; the G20S has no Y, so its Menu key does it. Menu stays a no-op in Settings for the state machine |
| D37 | In Settings the current section stays filled wherever focus is; a picked-up row's ring is teal; an off toggle is a `#2a2a3c` track with a `#a3a3b8` knob; Settings opens and closes without a tween | The design shows the on state and a static focus only; the motion table has no Settings row |
| D38 | Apps added from the menu get the next of the four accents with its default tint, the entry's Comment as description (else "Added from the app menu"), and an id from the desktop file name. Network and Sound run `cinnamon-settings network` and `cinnamon-settings sound` | apps.json requires these fields; SPEC says the panels launch like an app |
| D39 | Startup toggles `X-GNOME-Autostart-enabled` in `~/.config/autostart/boscamor.desktop` and keeps the file; with no file it shows "Not set up on this device" | The installer owns the entry; Cinnamon honours the key |
| D40 | `still_open` apps also carry `"asking"`: true when a dialog window is transient for that window. Still open shows "Asking to save" for those, "Still open" otherwise | The design shows both labels; a save prompt is a transient dialog |
| D41 | Web tiles (an app with a `url`) skip lookup step 3, the installed icon | Netflix, Prime Video and Browser all run Firefox; its logo would be wrong on them. A drop-in still works |
| D42 | Settings > Apps names the icon source ("Icon from apps.json", "Drop-in icon", "App's own icon") on rows with a real icon; rows with the built-in glyph say nothing | SPEC wants the source shown; the glyph is plainly the built-in one, and the design's rows stay as drawn |
| D43 | Still open is not in the SPEC navigation table. Left and Right move between its buttons; Back is Back to desktop; Home shows Home and leaves the apps open; Menu does nothing; Power opens the power confirm. The force-close confirm's Cancel and Back return to Still open | Nothing may close from one press, and Back should never lose work |
| D44 | Return closes only windows whose first type is NORMAL (no type counts as NORMAL unless the window is transient, then DIALOG), and skips WM_CLASS cinnamon, nemo-desktop, boscamor and launcher, and any window titled "Launcher" | SPEC's skip list, plus the launcher's own window, whose class is still to confirm on the box |
| D45 | Show me sends `show_window`; Back to desktop sends `{"cmd":"desktop","notify":false}`. Both leave the daemon in desktop mode, so the next Home runs Return again | The notification already went out when the desktop was first chosen |
| D46 | Dry run now also covers `wmctrl -i -c` (logged, not run), with `xkill` and the power commands | Tests and dev runs must never close real windows |
| D47 | Every InputMap event is saved with device -1 (all devices) | Events made in code default to keyboard device 16 and pad device 0, so a second pad matched nothing; found in step 9, test added |
| D48 | The Return shortcut is labelled "Return to the launcher" | SPEC calls the feature Return to Bosca Mór, but Law 7 keeps the name off screen, and the shortcut sits on the desktop and in the menu |
| D49 | The installer also installs `x11-utils` (xprop, xkill), `libnotify-bin` (notify-send), `sysstat` (pidstat), `intel-gpu-tools` and `curl` | The daemon calls those binaries, and the budget checks use pidstat and intel_gpu_top |
| D50 | The installer runs as the household user and uses sudo only for system steps; it refuses to run as root. `apps.json` and the autostart entry are created only when missing; every other file is rewritten only when it differs | gsettings and the user's files need the user's own session; Settings edits those two files, so a re-run must not undo the user's changes |
| D51 | `/opt/boscamor` belongs to the household user; the launcher autostarts with `--fullscreen`; the installer copies `build/boscamor` when it exists | `tools/deploy.sh` can then rsync without sudo, and the Godot export opens full screen without a project setting |
| D52 | The kiosk profiles' `user.js` also turns off the default-browser check, crash-restore prompt, welcome page, data-reporting notice and close-tabs warning | Prompts a remote can't answer would block the kiosk |
| D53 | `BOSCAMOR_ROOT` prefixes the installer's `/etc` and `/opt` paths, for tests only | Lets a second run be checked for "no changes" in a scratch folder without touching a real system |
| D54 | `tools/box-report.sh` collects the data the dev sessions need from the box (system, input devices, keycodes, desktop settings, windows as fixtures, budgets) into one `.tar.gz` | Chief relays it back after switching to the box; it never uses sudo itself |
| D55 | Dev on Windows (native Godot) plus WSL2 (daemon, installer); the Wyse only runs box checks, in three batches | Chief's Linux machines are low-power; Godot cross-exports Linux builds from Windows |
| D56 | `BOSCAMOR_HOME` and `BOSCAMOR_IPC` / `--dev-port` dev overrides | Keep dev files inside the repo, and let the Windows launcher reach the WSL2 daemon |
| D57 | A Windows build comes after Linux v1 works; OS-specific calls stay in the daemon and `paths.gd` | Chief wants one eventually; keeping screens OS-agnostic makes the port a daemon job, not a rewrite |
| D58 | D55 to D57 were first numbered D14 to D16 on origin, written alongside steps 1 to 9; they moved to the end on merge | The code already cites the D14 to D54 written here |
| D59 | Jellyfin's argv is `flatpak run org.jellyfin.JellyfinDesktop --fullscreen --tv`, taken from the `TV [Fullscreen]` action in `resources/meta/org.jellyfin.JellyfinDesktop.desktop` at jellyfin-desktop v2.0.0, the tag the Flathub manifest builds | Step 10 was asked for before switching to the box; the box report's Jellyfin section confirms it |
| D60 | Under `BOSCAMOR_HOME` the layout is `config/` (apps.json, icons/), `state/`, `cache/icons/`, `profiles/`, `autostart/` and `runtime/`. Installed apps' `.desktop` and icon folders don't move, `BOSCAMOR_RUNTIME_DIR` (D29) still wins for the runtime dir, and a launcher test's explicit `runtime_dir` wins over `BOSCAMOR_IPC` | SPEC only says everything sits under it; the system folders belong to other apps, and tests need their own daemon even on a dev shell that exports `BOSCAMOR_IPC` |
| D61 | Home keeps the last focused app's id as `last_app` in state.json. It saves once focus has rested 2 s after a move, on launch, when the launcher hides, and before a power action; an id no longer on Home falls back to the first tile. `StateFile.update` refuses `res://` paths | SPEC says persist it but not when; writing on every press would hit the disk during a held sweep. Tests point state at `res://` fixtures, which must never be written |
| D62 | Toasts have no design: a one-line panel at the top centre (`PAD_TOP` down), `#161622` fill with a 2 px `#2a2a40` border and 22 px radius (the dialog and button tokens), 100 px high, 32 px side padding, a 36 px coral alert glyph 24 px from 32 px DM Sans 500 text. It fades in and out with the confirm's 200 ms cubic out and holds 4 s. Toasts queue; while the launcher is hidden they wait, and the one on screen when it hides is dropped. Copy: "Couldn't open Plex", "Plex took too long to open", "Memory ran low while Plex was open" (or "Memory ran low") | SPEC asks for toasts but no step or design shows one; top centre is the one empty strip on Home, and a toast never takes focus or input |
| D63 | Two new daemon events: `{"evt":"app_window","id"}` when the launched app shows its first window, and `{"evt":"launch_timeout","id"}` when it shows none within 15 s, after which the daemon ends it the way Home does (SIGTERM, 3 s, SIGKILL, then `show`), `keep_on_home` or not. A window counts if it is a new `_NET_CLIENT_LIST` entry since the launch whose first type is NORMAL, DIALOG or SPLASH, not the desktop's or the launcher's. The list is read every 500 ms while waiting. With no readable window list the daemon sends `app_window` at once and times nothing. The launcher keeps its own 15 s deadline in DaemonClient's poll; whichever comes first returns Home with one toast | SPEC's IPC table has no window event. New clients, not `_NET_WM_PID`, because flatpak PIDs can be sandbox-local (D7). The poll is the one thing running while the launcher is hidden. Never killing apps on a box whose window list can't be read is the safe side |
| D64 | D61 to D63 were first numbered D60 to D62 on the spec-gaps branch, written alongside the paths helper's D60; they moved up one on merge | Both branches took D60 |
| D65 | After the launch fade the launcher stays full screen and black, paused, until the daemon reports the app's first window; the daemon raises that window (`wmctrl -i -a`), then the launcher minimises behind it. Desktop fades to black (the launch fade) before minimising. The window is restored only if it was minimised | First box test: minimising was plainly visible, with the desktop showing between Home and the app |
| D66 | On Linux, a launch with no daemon fails at once with the "Couldn't open" toast; the stand-in that fakes launches is for the Windows dev machine only | First box test: the daemon never started, and the stand-in hid it by pretending every launch worked |
| D67 | The daemon unit has no `[Install]`; the session autostart entry `boscamor-input.desktop` runs `systemctl --user restart boscamor-input.service` | Box report: Cinnamon never activates `graphical-session.target`, so SPEC's `WantedBy=graphical-session.target` would never start the daemon |
| D68 | The launcher is full screen by default (project setting, not only `--fullscreen`), has its own "Launcher" menu entry, and the installer clears `XF86PowerOff` from Cinnamon's `shutdown` binding as well | First box test: run by hand it opened windowed with a title bar; there was no menu entry; the box report showed Power bound to Cinnamon's shutdown |
| D69 | The launcher never minimises for an app: after the launch fade it stays full screen, black and paused (no redraws) behind it. The daemon raises the app's first window and keeps activating it every 500 ms, for up to 3 s, until one of the app's new windows has the focus; it raises the launcher (`wmctrl -F -a Launcher`) on every `show` and when an app closes on its own. This replaces D27's fallback and D65's minimise | Second box test: minimising behind the app was still plainly visible, and Muffin left the keyboard focus on the launcher until a click |
| D70 | Return to the launcher keeps waiting while a remaining window is asking to save (a transient dialog), up to 120 s, before it shows Still open | Second box test: Still open came up over the editor's save prompt after 5 s and took its focus |
| D71 | The installer sets Cinnamon's minimise effect (`org.cinnamon desktop-effects-minimize`) to `none` | Desktop still minimises the launcher; Chief chose to make that instant |
| D72 | Add app lists only Flatpak apps (the Flatpak exports), skipping any whose Flatpak id is already on Home, plus "A website": a name and address typed on the on-screen keyboard make a Firefox kiosk tile with its own profile seeded with the kiosk `user.js` (a copy in `launcher/data/user.js`, kept equal to the installer's by a test). The on-screen keyboard gains a Space key, and a keyboard's space bar types a space there | Second box test: the list showed every app on the system; Chief wants Flatpaks and websites |
| D73 | Each app row in Settings > Apps ends with a Remove button, reached with Right (after the start page, if any). It asks first, Cancel focused ("Remove <name>?"); Cancel and Back return to the same row. The app's Firefox profile is kept | Second box test: added apps could not be removed |
| D74 | No boot splash: `application/boot_splash/show_image` is off and the splash background is the BG token | Second box test: Godot's own splash showed; Law 7 allows only our own splash, and there isn't one |
| D75 | `tools/boot-splash.sh <png>` installs its own Plymouth theme (one picture, centred on BG, at up to 40% of the screen height) and makes it the default; `--restore` returns to Mint's. The picture is never committed; it stays on the box | Chief wants his own picture as the boot and shutdown splash. Law 7 allows a boot splash; a separate theme survives Mint updates; the repo is public |
| D76 | After the launch fade, an app that hasn't shown a window within 0.5 s gets a loading screen on the black: its tile (icon or glyph on its tint), "Opening <name>" and three dots pulsing in turn. The launcher stays awake for it, at up to 30 frames a second, and sleeps (paused, no frames) once the app's window is up. It goes on the window, a failure or the 15 s timeout | Chief: some apps take 10 to 15 s to open on the J4105, with only black to look at. No design exists; it reuses the tile and hero tokens plus new dot tokens |
| D77 | When the launched app's first window appears, the daemon leaves it behind the black launcher (loading screen still up) for 2 s more, then raises it, hands it the focus and sends `app_window`. The launcher's own backup deadline moves to 18 s (`LAUNCH_BACKUP`: the daemon's 15 s, plus the 2 s, plus 1 s) | Third box test: the desktop still blipped as apps opened; an app's first window often isn't full screen yet when it maps |
| D78 | When the launcher connects or is shown (`state` visible, `show`), the daemon activates its window (`wmctrl -F -a Launcher`) every 500 ms until it has the keyboard focus, for up to 15 s | Third box test: at login the remote did nothing until the screen was clicked; the desktop kept the focus after the launcher's window came up |
| D79 | The launcher sets the TV picture with xrandr on the first connected output that isn't a built-in panel (primary first): at login, every 5 s for the first 30 s, and each time it comes back. Settings > Display > Picture steps through 1920 x 1080 at 60 Hz (default), 1280 x 720 at 60 Hz and Automatic (`--auto`). A mode missing from the TV's list is added from the CEA-861 timing (`--newmode`, `--addmode`); if 1080p fails it falls back to 720p. A change asks "Keep this picture?" (Cancel focused) and goes back after 15 s, or on Cancel, Back or Home. The launcher runs xrandr, pactl and nmcli itself (`OS.execute`, never a shell) on a worker thread, each under `timeout 5` (Wi-Fi: 15 s and 45 s) with `LC_ALL=C`, and logs what it changed as `picture:`, `sound:` and `wifi:` lines; stdout is flushed on each print so they reach `~/.xsession-errors` at once | Third box test: through the active DP to HDMI adapter the box came up at the wrong mode until the cable was replugged; Chief wants 1080p60 set and kept, 720p60 at least. Law 6 lists binaries for the daemon only; these are the launcher's own Settings, and the worker keeps a stuck command from freezing the UI. New tokens: `SETUP_CHECK_EVERY`, `SETUP_BOOT_CHECKS`, `SETUP_CMD_TIMEOUT`, `PICTURE_KEEP`, `APP_REVEAL`, `LAUNCH_BACKUP`, `WIFI_SCAN_TIMEOUT`, `WIFI_CONNECT_TIMEOUT` |
| D80 | The launcher sets the sound with pactl (PulseAudio and PipeWire alike): the first card with an HDMI output gets the HDMI profile whose socket has a TV on it if exactly one says so, else `output:hdmi-stereo` ("Digital Stereo (HDMI) Output"); its sink becomes the default. The start volume (100%, 75% or 50%, default 100%) is set once per login and unmuted, so the remote's volume keys stick after that. Checked with the picture. Settings > Sound adds Sound output (HDMI / DisplayPort or Automatic, which leaves it alone), Volume at startup and Playing through; Open sound settings stays. The installer adds `x11-xserver-utils`, `pulseaudio-utils` and `network-manager` | Chief's setting: Built-in Audio's HDMI / DisplayPort output, Digital Stereo (HDMI) Output, volume 100%. The box report had no audio section yet, so the pactl fixtures are synthetic until the next one |
| D81 | Settings > Network lists Wi-Fi networks from nmcli (connected first, then strongest; hidden ones left out), with Search again. Accept joins: an open or saved network at once, a new one after its password is typed on the on-screen keyboard. A saved network whose password no longer works asks for it again; 802.1X networks point to the desktop's settings. The password goes to nmcli as an argument for the second it runs, and is never logged | Chief asked for Wi-Fi names and joining from the launcher. nmcli's other ways to pass a secret don't save it for the next boot; this box has one user |
| D82 | OK keys that X has no key for (`KEY_OK` 352, `KEY_SELECT` 353) are passed on by the daemon as `{"evt":"accept"}` while the launcher is on screen, and the launcher presses Accept | Third box test: with the G20S air mouse off, OK did nothing. Which code it sends then is still unknown; `--keys` now asks for OK with the mouse on and off and records presses that have only a scancode |
| D83 | The launcher reads `xrandr --verbose` and picks the mode by its exact timing, the CEA one first (1080p60: 148.5 MHz, 2200 x 1125; 720p60: 74.25 MHz, 1650 x 750), and sets it by id (`--mode 0x4a`). At login and on a Picture change the current mode counts only if it is that timing; when the launcher comes back from an app, any timing of the right size and rate is left alone. Each login check logs what the screen was on, the timings on offer and what it ran, as `picture:` lines in Godot's log (`~/.local/share/godot/app_userdata/Launcher/logs/`) | Third box report: the TV lists two different 1920x1080 modes at 60.00 Hz, and `--mode 1920x1080 --rate 60` takes the first, which may not be the one that works after a replug. The box still flickered at boot with v0.12.0. Lenient on return so a picture that works after a replug is never undone |
| D84 | The launcher uses Godot's Dummy audio driver (it plays no sound) and sleeps 16 666 us between loop iterations while shown (`SHOWN_SLEEP_USEC`, one 60 Hz frame; Godot's default is 6 900) | Third box report: 25% of a core idle on Home and 15% behind an app, against budgets of 1% and 0.5%. On Linux Godot's PulseAudio driver wakes about every millisecond even when silent. In WSL the change took the main thread from about 630 wakeups a second to 340 |
